# KI-2 旧版授权的「无账残留」：磁盘上有工作区写 SID 的 ACE，清单里却没有记录

[English](ki-2-orphaned-grant-cleanup.en.md) ｜ 简体中文

- **状态**：插件侧历史缺陷（`0.2.0-beta.1` 及更早版本），根因已修，残留可用本插件自带的
  scan/revoke 工具识别与清理。
- **影响范围**：在受影响版本上使用过「沙箱授权目录」（Windows）且发生过下述任一情形的机器；
  受影响目录的 DACL 上留有工作区写 SID（`S-1-4-…`）的 ACE。
- **首次记录**：2026-10-04（授权清单 v2 改造时定性）。

### 现象

- 旧版「沙箱授权目录」的授权情况**完全不可见**：界面上看不到哪些目录被授过权，
  也没有任何清单文件可查；
- 在安全属性 / `icacls <目录>`（示例，请替换为你的实际目录）里能看到 `S-1-4-…` 的
  `(OI)(CI)(W,D,DC)` ACE，但：
  - 对应目录早已从授权配置里删除，或
  - 根本找不到对应关系（工作区目录已改名 / 已删除，配置无从对起）；
- 这些 ACE 是**常驻**的：跨进程重启仍然存在，不会被自动回收。

### 触发条件（历史缺陷，何以产生无账残留）

工作区写 SID 的 ACE 一旦物化就是操作系统里的常驻状态，回收它需要显式的撤销动作。
旧版本（`0.2.0-beta.1` 及更早）的缺陷在于**清单不记账**：

1. 授权随每次解析即时物化到 DACL，但 `grants.json` 不记录运行期物化的结果；
2. 于是「配置删除 → 撤销对账」这条链查不到账：清单里没有的目录不会被对账回收；
3. 叠加两种放大情形：
   - **工作区改名/删除**：写 SID 由工作区规范路径派生，路径一变 SID 就变——旧 SID
     的 ACE 成了孤儿，配置里再也对不回去；
   - **清单文件损坏/丢失**：即使新版有清单，文件一丢同样退回「无账可查」。

### 根因

- 旧版 `grants.json` 只在启动对账时重建，运行期物化不落盘（清单滞后缺陷）——
  根因已修：v2 清单随每次物化/撤销**即时落盘**；
- ACE 是常驻 OS 状态，**跨重启存活**，没有账本时没有任何机制能发现它们。

### 处置（scan → 人工确认 → revoke）

识别与清理**不依赖清单**：工作区写 SID 可以从工作区路径纯计算重算出来（工作区目录
已删除也能算）；不知道路径时，按 DACL 形状匹配 `S-1-4-<x>-<y>`（恰好两个子授权——
第三段以 `-1` 结尾的是私有临时目录 SID，可区分；常规 Windows 文件几乎不会出现
authority-4 的 ACE，误伤面趋近于零）。

以下命令均在**非受限终端**（能改 DACL 的令牌）里运行；路径全部为
**示例，请替换为你的实际目录**：

```bash
# 1) 扫描：默认范围 = 授权清单里记录的根 ∪ 其模式展开；也可以显式指定任意范围
node scripts/verify-ace.mjs scan
node scripts/verify-ace.mjs scan "D:\Shared"
#    --deep 关闭根剪枝（默认根目录 DACL 无命中即跳过整棵子树），
#    用于「父干净、子有显式残留」的零星情形；整盘扫描以分钟计，慎用
node scripts/verify-ace.mjs scan --deep "D:\Shared"

# 2) 审阅命中清单：每条标注 explicit / inherited-copy（显式 ACE / 继承副本）与
#    账内 / 无账（当前清单是否记录该路径）——无账命中即清理候选

# 3) 确认后批量剥离（会再次列出命中并要求输入 yes 确认；--yes 跳过确认）
node scripts/verify-ace.mjs revoke "D:\Shared"

# 4) 复扫验证归零
node scripts/verify-ace.mjs scan "D:\Shared"
```

注意：

- revoke 会剥离确认范围内**全部**命中（含「账内」标注的）——确认前看清标注；
  只想清无账残留时，缩小范围或用 `--sid S-1-4-…` 指定目标 SID；
- 形状匹配理论上存在极小误伤面（外部软件写 authority-4 的 ACE），因此 revoke
  强制人工确认清单，`--yes` 才跳过；
- 脚本需在本机直接运行（受限令牌改不了 DACL，会在物化/剥离一步报 Win32 错——
  那本身即是答案：换非受限终端）。

### 预防

- `0.2.0-beta.1` 之后交付的**授权清单 v2**：清单随运行期授权/撤销即时落盘
  （记录含状态、授权时间、来源 pattern、排除标志、失败原因与撤销历史），不再滞后；
- 撤销失败不再静默丢弃：进入 `pendingRevoke` 待重试，每次对账自动重试直至成功入史；
- 设置页删除授权目录（或会话区面板执行撤销）即触发对账回收——正常使用不再产生
  新的无账残留，ki-2 工具仅在异常现场（清单丢失、旧版遗留）启用。

### 相关

- 撤销语义与排除机制详见权限配置指南的撤销章节。
