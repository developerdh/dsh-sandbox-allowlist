# docs/ 目录使用说明

> 本文件写给在本仓库工作的协作者与 AI Agent：说明 `docs/` 的目录结构、文档落位
> 规则与双语同步纪律。仓库级约束（隐私红线、占位规范）见根目录
> [AGENTS.md](../AGENTS.md)，本文不重复、只做补充。

## 目录结构

```
docs/
├── agents.md                          本文件：目录使用约定
├── development.md / .en.md            维护者文档：测试套件、构建部署、内部契约、包结构
├── guides/                            面向使用者的说明文档
│   ├── permission-rules.md / .en.md   三类权限规则指南（唯一的完整配置参考：
│   │                                  语法、语义、判定流程、场景示例、排障速查）
│   └── architecture.md / .en.md       工作原理、安全边界、已知限制
├── testing/                           测试执行计划（供会话中的执行 agent 按步骤跑）
│   └── test-plan-permissions.md / .en.md
├── issues/                            已知问题：背景、现场表现、处置办法
│   └── ki-1-session-controller-reload-race.md
└── internal/                          内部工作文档（版本升级方案、设计原型等；
    ├── upgrade-plan-0.2.0-rc.2.md     不对用户承诺内容，不进 README 索引）
    └── config-ui-prototype.html
```

`docs/temp/`（如存在）是本地草稿区，**不入库**（保持未跟踪），不写任何会被引用
的内容。

## 文档落位规则

写新文档（或让 AI 写）时按受众落位：

| 内容 | 位置 |
|---|---|
| 使用方法、配置语义、场景示例、排障 | `guides/`；若是小节级补充，优先并入既有指南对应小节，不新开文件 |
| 安装/快速开始等门面信息 | 根目录 `README.md` / `README.en.md`（docs/ 不放门面内容） |
| 测试套件、构建部署、内部契约、包结构 | `development.md`（小改动直接并入对应小节） |
| 一次性的会话内验证脚本/计划 | `testing/`，一个计划一个文件 |
| 线上问题、竞态、应急处置 | `issues/`，命名 `ki-<编号>-<短名>.md`；问题根治后保留文档并标注状态 |
| 升级方案、原型、过程底稿 | `internal/` |

判断标准：**删除一个文件时谁会受影响**——用户受影响的进 `guides/`，维护者受影响
的进 `development.md`，没人受影响的进 `internal/` 或不写。

## 双语纪律

- 中文 `*.md` 为真源，英文 `*.en.md` 为逐段镜像；**改中文必须同步改英文**，
  两份文件结构保持一致（标题、小节顺序一一对应）。
- `README.md` / `README.en.md` 是门面对，结构一一对应，语言切换链接放文件头部第一行。
- 每份文档头部放一行语言切换链接（形如 `English → xxx.en.md ｜ 简体中文`）与适用版本。
- 引用其他文档用相对链接；中英两版各自指向同语言的版本。

## 写作规范

- 遵守根 [AGENTS.md](../AGENTS.md) 的隐私红线：任何示例不得出现本机真实路径、
  用户名、凭据；示例路径一律用占位（`D:\Shared\Tools`、`C:\Users\me` 等）并注明
  「示例，请替换为你的实际目录」。
- 版本相关表述写明适用版本（当前 `v0.2.0-beta.1`，兼容基线 dsh `0.2.0-rc.2`）；
  过时表述随改动就地修正，不留「0.1.5 时代」的旧话。
- 事实变更（配置存储位置、生效机制、兼容基线）先核实再落笔：以代码与真机行为
  为准，不凭旧文档转述。
- 措辞克制：不写营销语气；安全相关表述明确「能拦什么 / 拦不了什么」，不夸大覆盖。
