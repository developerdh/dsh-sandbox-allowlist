# M1-03/04/05 真机验收用例（人工执行）

> 自动化测试计划见 [m1-03-04-05-test-plan.md](m1-03-04-05-test-plan.md)。
> 本文档的用例涉及真实 GUI 交互、真实 DACL 与版本升级，需人眼断言，故人工执行。

## 0. 为什么不全自动交给会话代理

- **断言需要人眼**：焦点恢复、弹层遮罩、悬停气泡定位等 GUI 行为，会话代理（无屏幕）
  无法观测；
- **自引用风险**：代理运行在待测插件自己的沙箱内，升级写安装目录、剥离 DACL 均在
  授权范围外，每步触发审批；且 `verify-ace revoke` 要求**非受限令牌**（受限令牌改不了
  DACL），审批放行的仍是受限令牌，测试会卡死；极端情况下代理撤销了自己工作区的
  授权，会话失去写权限无法自救；
- **可委托边界**：只读与准备类步骤（下表标注「代理可辅助」）可交给 dsh 会话代理
  代跑，破坏性步骤（revoke、升级、改安装目录）必须人工在非受限终端执行。

## 1. 通用前置条件

- Windows 10/11；dsh ≥ 0.2.0-rc.2；本插件已安装且已启用（设置页可见「沙箱授权」分节）；
- 一个**非受限终端**（普通 PowerShell/CMD，非 dsh 会话内）用于所有 DACL/工具命令；
- dsh 主目录（下称 `<dsh 主目录>`，默认 `%USERPROFILE%\.dsh`，**示例，请替换为你的
  实际目录**）下的清单文件：`<dsh 主目录>\sandbox-allowlist-grants.json`（下称「清单」）；
- 示例路径声明：下文 `D:\Shared\Tools`、`D:\Shared\Leftover` 等均为**示例，请替换为
  你的实际目录**；操作前建议备份清单文件；
- 清单是运行期派生态：宿主只在实例启动时加载一次，**运行中手工修改清单文件对当前
  实例不生效**（面板「刷新」也只反映内存账本，不重读文件），重启后才按文件内容重建；
- 会话区授权状态面板入口：会话头部工具区的盾牌/状态按钮（下称「面板」）。

## 2. 用例

### A1 面板基础查看（新装/正常态）

- **目的**：验证面板数据通道与四态渲染。
- **前置**：至少一个授权目录已生效；有一个进行中的会话，cwd 即该工作区。
- **步骤**：
  1. 打开面板；
  2. 核对表格列（路径/状态/时间/原因/来源/操作）与行数；
  3. 逐行悬停查看气泡；点状态过滤器切换四种状态。
- **预期**：配置内授权目录显示「已授权」绿点，时间为本地墙钟格式
  `YYYY-MM-DD HH:MM:SS`，来源列为覆盖它的 pattern；空态文案
  「当前工作区暂无授权记录。」仅在确实无记录时出现；过滤器行数正确；气泡贴按钮
  正下方居中、长文案贴视口边缘时收进。
- **代理可辅助**：无（纯 GUI）。

### A2 v1 旧清单升级（迁移 + 补记时间）

- **目的**：验证旧版数据的升级显示路径与自愈。
- **前置**：A1 通过；备份清单。
- **步骤**：
  1. 关闭 dsh，把清单中目标工作区的值整体替换为 v1 形态（字符串数组，如
     `["D:\\Shared\\Tools"]`），保存；
  2. 启动 dsh，打开面板；
  3. 观察该目录行（此时应显示「已授权」、时间列「—」）；
  4. 等待首次对账完成（或触发一次配置保存/新会话解析），点面板「刷新」。
- **预期**：第 2 步即能看到 v1 记录以「已授权」呈现（迁移在内存完成，不丢行）；
  第 4 步后时间列从「—」变为有效时间（补记确认时间）；清单文件被写回 v2 结构
  （含 `status`/`grantedAt`/`fromPatterns` 等字段）；v1 里存在但配置已不含的路径
  被自动剥 ACE 并转入「已撤销」。
- **代理可辅助**：步骤 1 的文件改写、步骤 4 后的清单文件核对。

### A3 清单损坏自愈

- **目的**：验证账本损坏后的重建，以及恢复结果在面板上的可见性路径。
- **前置**：A1 通过；备份清单。
- **步骤**：
  1. 关闭 dsh，把清单内容改写为非法 JSON（如截断一半）；
  2. 启动 dsh，打开面板；
  3. 等待首次对账后检查清单文件；
  4. 点面板「刷新」；若仍为空态，做一次会话活动（任一工具调用，或重新触发会话），
     再打开面板或刷新。
- **预期**：
  - 面板全程不报错、不崩；
  - 清单文件被重写为合法 v2；目录 DACL 上 ACE 幂等重涂（`icacls "<目录>"` 可见
    工作区 SID ACE）；
  - 面板行的可见性以「该工作区被重新解析」为准：「刷新」只反映宿主内存账本
    （不重读清单文件、不触发对账），而启动对账重建的工作区键未必是当前会话的键，
    所以步骤 4 的刷新可能仍为空态——这不是故障；会话活动触发策略解析后，
    配置内目录以「已授权」出现，时间为有效时间。
- **代理可辅助**：步骤 1、步骤 3 的文件与 `icacls` 核对。

### A4 无账残留：发现与清理（KI-2 主链路）

- **目的**：验证「账面看不到的 ACE」只能被 scan 工具发现并清理，面板行为符合设计。
- **前置**：A1 通过；一个不在配置中的目录（示例 `D:\Shared\Leftover`，**请替换**）。
- **步骤**：
  1. 先正常授权目录 X（如 `D:\Shared\Tools`）；
  2. 关闭 dsh，**手工删除清单中 X 的记录**（模拟清单丢失/无账），保存后启动 dsh
     ——无账状态必须重启后才对实例成立（运行中实例的内存账本不受文件删改影响）；
  3. 在设置页删除授权目录 X（运行中删除配置不立即触发回收——回收发生在下一次
     实例启动对账时，而此刻无账可查，ACE 不会消失）；
  4. `icacls "D:\Shared\Tools"` 确认 DACL 仍带 `S-1-4-…` ACE —— 即无账残留；
  5. 打开面板确认**看不到**该目录（预期：账面为空，这就是设计边界）；
  6. 非受限终端运行 `node scripts/verify-ace.mjs scan "D:\Shared"`（示例范围）；
  7. 审阅命中：确认该条标注「无账」；随后 `node scripts/verify-ace.mjs revoke "D:\Shared"`
     （按提示输入 `yes`）；
  8. 复扫 `scan` 确认归零；`icacls` 复核 ACE 已消失。
- **预期**：面板查不到无账残留（账本只记账内状态）；scan 能发现并正确标注；
  revoke 后残留归零；revoke 强制人工确认（不输 yes 不执行）。
- **代理可辅助**：步骤 2 的文件改写、步骤 4、6、8（scan 为只读）；步骤 7 必须人工。

### A5 假账纠正（账面已授权、实际无 ACE）

- **目的**：验证「账实不符」可通过面板撤销→恢复强制重物化纠正。
- **前置**：A1 通过；非受限终端可剥 ACE。
- **步骤**：
  1. 正常授权目录 Y（示例 `D:\Shared\Tools` 子目录，**请替换**），确认面板「已授权」；
  2. 非受限终端用 `icacls "<Y>" /remove:sid <S-1-4-…>` 剥掉工作区 SID ACE
     （SID 可从 scan 输出或 `icacls` 全量输出获得）——此刻账面仍是「已授权」但实际无 ACE；
  3. 沙箱内对 Y 内文件执行写操作，观察被 OS 拒绝；
  4. 面板对该行点「撤销」→ 确认层确认 → 完成后再在「已撤销」行点「恢复」→ 确认；
  5. 沙箱内重试写操作。
- **预期**：撤销（对无 ACE 目录剥离为幂等成功）入 history；恢复后行回到「已授权」
  且时间是**新**时间；DACL 重新物化（`icacls` 可见）；第 5 步写操作成功。
- **代理可辅助**：步骤 2 的 `icacls`、步骤 3/5 的写操作与结果观察。

### A6 撤销/恢复/重试授权交互与焦点回归

- **目的**：验证面板操作链路与 Electron 焦点回归（electron#31917）。
- **前置**：A1 通过；存在 granted / failed / 待回收三种行更佳（failed 可临时对
  无权限目录授权制造）。
- **步骤**：
  1. 点「撤销」→ 出现确认层（标题/正文/双按钮）→ 点遮罩取消 → 无请求发生；
  2. 重新点「撤销」→ 确认 → 操作期间出现 busy 层 → 完成后行转入「已撤销」；
  3. **关键**：关闭确认层与 busy 层后，立即点击会话输入框并键入；
  4. 对 failed 行点「重试授权」（先修复目录权限）。
- **预期**：确认层取消不发请求；确认后恰好执行一次；busy 层可感知（亚秒操作也
  有最短展示）；**会话输入框可立即聚焦键入**（焦点不丢）；重试后 failed 行转
  「已授权」+ 新时间。
- **代理可辅助**：无（纯 GUI）。

### A7 工作区解析语义

- **目的**：验证面板只看当前会话工作区。
- **前置**：两个工作区分别有授权记录（如工作区甲、乙各有配置）。
- **步骤**：
  1. 在工作区甲的会话打开面板 → 核对工作区指示器显示甲、数据为甲的记录；
  2. 新建 cwd 在乙的会话打开面板 → 指示器显示乙；
  3. 在 cwd 不匹配任何清单键的会话打开面板。
- **预期**：1/2 各自正确；3 显示「当前工作区暂无授权记录。」空态，**绝不**显示
  别的工作区或最近使用的记录（设计如此，不是数据丢失）。
- **代理可辅助**：无（纯 GUI）。

### A8 审批弹框多行展示（可选，覆盖客户端 CSS 补丁）

- **目的**：验证结构化 reason 在真机按多行渲染。
- **步骤**：触发一个不可自动放行的命令（未命中放行规则的删除类命令）。
- **预期**：弹框 headline 按 `[sandbox-allowlist]` 前缀 + 结论/原因/分解/建议分行
  展示（`pre-wrap` 生效）；内容过长时弹框内部滚动、不撑破布局。
- **代理可辅助**：步骤（由代理发起命令即触发弹框）；断言人工。

### A9 版本差窗口自愈（可选）

- **目的**：验证入口探测的 12s 重试窗口。
- **步骤**：页面已打开时重载插件（如重启 dsh 服务端）并立即刷新 Web 页面，
  使「页面先到、路由未就绪」。
- **预期**：入口按钮在约 12 秒内自动出现，而不是永远不出现；期间无报错。
